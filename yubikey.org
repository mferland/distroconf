#+title: YubiKey 5 NFC setup on Arch Linux and Omarchy

* Before enrolling the key

- Keep recovery codes and an independent way to sign in to every account.
- Where a service permits it, register at least two security keys and test both
  before removing an existing authentication method.
- Do not commit PINs, recovery codes, PAM enrollment data, or other key
  material to this repository.
- A FIDO reset deletes every FIDO2 and U2F credential on the YubiKey. Do not run
  ~ykman fido reset~ as a troubleshooting step.

The instructions below use USB for initial management and enrollment. NFC use
on a computer requires a compatible PC/SC reader and support from the
application or browser; the YubiKey's NFC capability alone is not sufficient.

* Install and inspect the key

Install the command-line manager and FIDO2 tools through Omarchy's package
helper:

#+begin_src sh
omarchy pkg add yubikey-manager libfido2
#+end_src

Insert the YubiKey over USB, then confirm that it is detected:

#+begin_src sh
ykman list
ykman info
ykman fido info
fido2-token -L
#+end_src

Set the FIDO2 PIN interactively. Do not pass the PIN as a command-line option,
because command lines can be retained in shell history and exposed to other
processes.

#+begin_src sh
ykman fido access change-pin
ykman fido access verify-pin
#+end_src

A new YubiKey has no FIDO2 PIN by default. Eight consecutive incorrect PIN
attempts lock the FIDO application and require a destructive FIDO reset, so
stop and verify the PIN instead of repeatedly guessing.

* Register the key with websites

In each service's security or multi-factor-authentication settings, add a
security key or passkey and follow the browser prompts. Register the backup
YubiKey separately, save recovery codes offline, and test both keys before
removing the previous sign-in method.

WebAuthn enrollment is service-specific and should not be automated or stored
in this repository.

* Use the YubiKey for SSH

Hardware-backed SSH key creation, recovery on the work workstation, and
per-host client configuration are documented in [[file:ssh.org::*Hardware-backed keys with a YubiKey][the SSH setup guide]].
Website security-key enrollment and local PAM enrollment remain separate.

* Use an SSH agent and reuse connections

Use this setup on either workstation after creating or recovering the SSH
credential. The agent holds its local handle and caches the handle's file
passphrase. It does not cache permission to bypass the YubiKey's PIN and touch
requirements. Multiplexing reduces touches by reusing an already authenticated
connection for the same remote user, host, and port.

** Load the credential into the agent

Use the agent provided by your desktop session. Check it from a terminal:

#+begin_src sh
ssh-add -l
#+end_src

"The agent has no identities" means an agent is available but empty. If the
command instead reports that it cannot connect to an authentication agent,
start one for the current terminal and its child processes:

#+begin_src sh
eval "$(ssh-agent -s)"
#+end_src

This fallback is for the current terminal; do not run it in every terminal's
shell startup file. Other terminals should use the desktop session's agent.
Load the handle once per agent session, substituting your work credential's
filename if you created a separate one:

#+begin_src sh
ssh-add ~/.ssh/id_ed25519_sk_yubikey
ssh-add -l
#+end_src

** Configure a one-hour idle timeout

Create a private directory for the connection control sockets:

#+begin_src sh
mkdir -p ~/.ssh/control
chmod 700 ~/.ssh/control
#+end_src

Merge the following into ~~/.ssh/config~ for each intended work host. Replace
~github.com~ with your actual host or SSH alias, and adjust ~IdentityFile~ if
needed. Put this entry before general ~Host *~ defaults, since SSH uses the
first value found for most settings:

#+begin_src conf
Host github.com
    IdentityFile ~/.ssh/id_ed25519_sk_yubikey
    IdentitiesOnly yes
    AddKeysToAgent yes
    ForwardAgent no
    ControlMaster auto
    ControlPath ~/.ssh/control/%C
    ControlPersist 1h
    ServerAliveInterval 60
    ServerAliveCountMax 3
#+end_src

The first connection authenticates with the YubiKey. Further SSH, Git, SCP,
and SFTP operations using the same connection reuse that authentication.
~ControlPersist 1h~ closes the master after one hour with no attached sessions;
it is an idle timeout, not a maximum connection age. Regular use can keep it
available throughout the day. Keepalives help detect a broken connection but
do not prevent server timeouts or network/VPN interruptions.

Expect another PIN verification and touch when connecting to a different
destination, after the idle timeout, or after the connection is lost. This
setup reduces repeated touches; it cannot guarantee one touch for the entire
day. With ~verify-required~, your agent must support prompting for user
verification. If it cannot sign, use a compatible OpenSSH agent with a working
askpass prompt, or use ~IdentityAgent none~ for that host to authenticate
directly; multiplexing still provides connection reuse.

** Check reuse and close a connection

Inspect the effective settings without making a network connection:

#+begin_src sh
ssh -G github.com | grep -E '^(identityfile|identitiesonly|addkeystoagent|forwardagent|controlmaster|controlpath|controlpersist|serveraliveinterval|serveralivecountmax) '
#+end_src

Connect, then check the master and connect again:

#+begin_src sh
ssh -T git@github.com
ssh -O check git@github.com
ssh -T git@github.com
#+end_src

For GitHub, successful authentication reports that shell access is unavailable
and exits with status 1. The second connection should reuse the master without
another touch. For other hosts, substitute the actual user and host throughout.

Unplugging the YubiKey or removing its handle from the agent does not close an
authenticated connection. It remains usable until it disconnects or reaches
the idle timeout. To close it explicitly when leaving work:

#+begin_src sh
ssh -O exit git@github.com
#+end_src

This also disconnects any shells, tunnels, or transfers using that master.
Repeat for each destination you used. The next connection requires fresh
authentication. There is no device-removal watcher in this setup.

* Optional: use the key for sudo authentication

This is optional and can lock out administrative access if configured
incorrectly. Keep a root shell open, retain password authentication, and test
in a second terminal before closing the recovery shell.

Install the PAM module and create a per-user enrollment file. If that file
already exists, back it up and review it instead of overwriting it:

#+begin_src sh
omarchy pkg add pam-u2f
mkdir -p ~/.config/Yubico
chmod 700 ~/.config/Yubico
pamu2fcfg > ~/.config/Yubico/u2f_keys
chmod 600 ~/.config/Yubico/u2f_keys
#+end_src

To enroll a backup key for the same account, insert it and append its mapping:

#+begin_src sh
pamu2fcfg -n >> ~/.config/Yubico/u2f_keys
#+end_src

Back up ~/etc/pam.d/sudo~, then add the following line before its existing
~auth~ rules:

#+begin_src conf
auth sufficient pam_u2f.so cue
#+end_src

This initial policy means “YubiKey or the existing password”; it is not strict
two-factor authentication. Test both paths in another terminal:

#+begin_src sh
sudo -k
sudo true
#+end_src

Do not make ~pam_u2f~ required for sudo, login, the lock screen, or display
manager authentication until a recovery path and the exact PAM control flow
have been tested. The mapping file binds a local user, host, and hardware key,
so it remains local rather than being tracked by distroconf.

* Optional: enable smart-card applications

PIV and OpenPGP use the smart-card stack and have PINs and credentials separate
from FIDO2. Install their transport tools without initializing or resetting the
applications:

#+begin_src sh
omarchy pkg add pcsclite ccid opensc
sudo systemctl enable --now pcscd.socket
ykman piv info
ykman openpgp info
#+end_src

A PIV or OpenPGP key ceremony needs a separate plan for PINs, management keys,
certificate or subkey backups, and revocation material. Do not reset either
application merely to explore it.

* Troubleshooting

Start with non-destructive checks:

#+begin_src sh
ykman list
ykman info
ykman fido info
fido2-token -L
journalctl -b --no-pager | grep -Ei 'yubi|fido|hidraw|pcsc'
#+end_src

For PIV, OpenPGP, or an NFC reader, also inspect the smart-card service:

#+begin_src sh
systemctl status pcscd.socket
#+end_src

Reinsert the key directly into the computer rather than through a hub, try a
different USB port, and confirm that a browser or other process is not already
using it. Do not work around device-access errors by making ~hidraw~ devices
world-writable.
